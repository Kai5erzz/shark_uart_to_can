# USART2 RAW 双向测试实板记录

2026-10-31，Asia/Shanghai。当前结论：固件和两端测试页面已实现；内部回环长文本通过，外部链路曾短包成功，但随后出现发送失败和长文本丢字节，**外部双向透传未通过验收**。

## 设备和固件

| 项目 | 本次配置 |
|---|---|
| 目标固件 | 当前 Release，Flash 49880 B，RAM 28496 B |
| BIN SHA-256 | `637f95358674d942a08eb164531501abe6969f04b494bb5a033bd91d6da274e4` |
| 下载 | DAPLink / SWD，`shark_program`，写入与校验49880 B成功 |
| UART2 | DAPLink自带串口，`/dev/ttyACM1`，921600 8N1；用户确认连接到PA2/PA3 |
| USB-CAN | HDSC旧CDC，`/dev/ttyACM0`，达妙旧协议，Classical CAN 1 Mbit/s |
| 板上保存 ID | 十进制5，即标准 CAN `0x005`；测试未更改保存值 |
| 外部硬件 | 用户确认共地、CANH/CANL、终端与稳定5V供电；这些电气状态未由软件实测 |

## 测试结果

| 场景 | 发送 / 接收 | 结果 |
|---|---:|---|
| USART2→板上CAN内部回环→USART2，16KiB ASCII | 16384 / 16384 B | PASS，逐字节和SHA-256一致 |
| 外部CAN，同ID立即回传，重新插接后短文本 | 30 / 30 B | PASS |
| 外部CAN，16KiB目标，32B/5ms写入 | 288 / 33 B后停止 | FAIL，偏移32首次不一致；适配器报告1次发送失败 |
| 随后8B/2ms及8B/5ms写入 | 各256 / 0 B | FAIL，超时，Monitor均无新CAN RX |
| 独立Monitor→CAN→USART2，4KiB目标，2ms帧间隔 | 4096 / 0 B | FAIL，适配器512次发送失败状态 |
| 再次复位后单帧正向/反向 | 8B各一帧，无到达 | FAIL，表明当前故障不限于长文本负载 |

内部回环使用当前Release镜像，仅通过调试器临时切换控制器状态，完成后恢复正常CAN模式。其耗时2.776秒包含主机节拍和末尾100ms静默检查，不能作为单向转发延迟。收发SHA-256均为 `19bbd5358795bdd498773524c518031c86b3535e3dd0f5072b044364886fcb52`。

外部长文本失败时，Monitor正确接收318字节（含前一项30字节），并提交同ID回复；其中一条返回被分析仪以 `CMD=0x02` 报告发送失败。助手在错误位置停止，没有误报PASS。随后链路不通时，SWD可见USART2仍累计收到输入，CAN发送在等待，控制器有仲裁阶段协议错误/位错误记录。此证据无法独立确定是接触、收发器、分析仪状态还是其他电气/时序问题；不能仅凭内部回环排除外部模式的软件配置问题。

## 可复查记录

- `build/uart2-raw-flash.log`：当前Release烧录、校验和复位。
- `build/performance/uart2-raw-internal-loopback.json` 及 `.tx.txt` / `.rx.txt`：16KiB内部回环。
- `build/performance/uart2-raw-replug-short.json`：重新插接后30B短包成功。
- `build/performance/uart2-raw-replug-long.json`：长文本差异偏移、收发原文。
- `build/performance/uart2-raw-external-8b-2ms.json`、`...-8b-5ms.json`：后续超时。
- `build/performance/uart2-raw-independent-reverse.json`、`uart2-raw-replug-monitor.json`：独立反向和适配器失败计数。
- `build/performance/uart2-raw-external.json`：重新插接前的首次外部失败，含SWD状态。

需要先恢复稳定的单帧正向/反向，再按 [双向透传测试指南](uart2-raw-test.md) 重测长文本、独立反向和持续压力。旧USB性能报告属于改动前的固件，不替代本轮验证。当前未达到封版条件。
